# Портфолио — Нестеренко Иван

Личный сайт: дизайн, вёрстка, разработка. Чистые HTML, CSS и JS без сборщика
и без зависимостей — открыл файл, поправил, обновил страницу.

**Живой сайт:** https://folvski.github.io
**Как публиковать:** [DEPLOY.md](DEPLOY.md)

Макет: `Mine portfolio WebSite` (Figma). Брейкпоинты `1920 · 1440 · 1024 · 768 · 390`.
Контейнер `1136px` на десктопе, `656px` на `≤1024`, на телефоне — вся ширина
минус поля. На `≤1024` меню сворачивается в бургер.

## Как запускать локально

Страницы подключают шапку, подвал и общие секции через `fetch`, поэтому
**двойным кликом файл не откроется** — браузер заблокирует запрос к `file://`.

Нужен локальный сервер с корнем в папке `Site`:

- VS Code → расширение **Live Server** → правой кнопкой по `index.html` → *Open with Live Server*
- или `npx serve .`
- или `python -m http.server 5500`

Корень сервера — именно `Site`, а не папка выше: все пути в разметке абсолютные
(`/assets/...`, `/views/...`).

   │  ├─ base/                tokens, reset, typography, layout, utilities
   │  ├─ components/          Кнопка, бейдж, чип, карточка, шапка, курсор, шторка…
   │  └─ sections/            Стили конкретных секций

Раскладка по слоям: `data/` — модель, `views/` и `css/` — представление,
`js/controllers/` — поведение.

## Контроллеры

Каждый отвечает ровно за одно. Подключаются в `main.js`, **порядок важен**:
партиалы подставляются первыми, иначе контроллерам нечего искать в DOM.

| Файл | Что делает |
| --- | --- |
| `menu.js` | Бургер и подсветка текущей страницы |
| `reveal.js` | Появление блоков при прокрутке (`data-reveal`, `data-appear`) |
| `contacts.js` | Собирает карточки контактов из `data/site.js` |
| `pack.js` | Укладывает пилюли со стеком плотнее обычного переноса |
| `shine.js` | Блик, ползущий по обводке пилюль одна за другой |
| `works-nav.js` | Строка разделов на «Работах»: подсветка и сворачивание в стопку |
| `smooth-scroll.js` | Плавная прокрутка колесом |
| `anchors.js` | Переходы по якорям с учётом высоты шапки |
| `page-fade.js` | Переход между страницами через чёрный |
| `to-top.js` | Кнопка «наверх» |
| `cursor.js` | Свой курсор — стеклянный кружок вместо стрелки |

Всё, что связано с движением, выключается при системной настройке
«уменьшить движение», а курсор и плавная прокрутка — ещё и на тачскрине.

## Правила

- **Токены только в `base/tokens.css`.** В остальных файлах — `var(--…)`,
  никаких хардкод-значений цвета, отступа и радиуса.
- **Один файл — одна сущность.** Новый компонент = новый файл в `components/`
  плюс строка `@import` в `main.css`.
- **Настройки — переменными сверху блока.** У карточек, курсора, блика и стопки
  разделов ручки собраны в начале правила и подписаны: что крутить, чтобы
  поменять поведение. Числа по месту не правим.
- **Акцент внутри текста — только цвет.** `strong` наследует начертание
  (`base/typography.css`), жирный акцент в абзаце не используется.
- Секция, которая есть больше чем на одной странице, живёт в `views/sections/`
  и подключается через `data-include`.
- Карточки проектов свёрстаны статикой в HTML — так их видят поисковики.
- Названия соцсетей и ссылки на них лежат в `data/site.js`, а не в разметке:
  блокировщики рекламы вырезают такие узлы по содержимому прямо из ответа сервера.

## Картинки

На сайте используются `.webp` — они в среднем в семь раз легче исходников.
Оригинальные `png` и `jpg` лежат рядом, под теми же именами, и остаются
источником: webp сжат с потерями, пересохранять из него же нельзя. В репозиторий
оригиналы не попадают, их отсекает `.gitignore`.

Добавляя картинку: положи оригинал, сделай рядом `.webp`, ссылайся на `.webp`.

Единственное исключение — `assets/img/icons/Preview.png`. Это превью для карточки
ссылки в мессенджерах, и боты, которые её собирают, webp понимают не все.

## Регистр имён файлов

На Windows `Merra.png` и `merra.png` — один файл, на серверах GitHub это разные
файлы. Картинка, которая прекрасно видна локально, на опубликованном сайте даст
пустое место. Добавляя файлы, сверяйте имя в разметке с именем на диске
посимвольно.
