# Публикация на GitHub Pages

Итог: сайт лежит по адресу **https://folvski.github.io** — бесплатно, с https,
без срока годности. Правка выкладывается тремя командами и появляется на сайте
примерно через минуту.

---

## Почему репозиторий называется именно так

Все пути в разметке абсолютные: `/assets/css/main.css`, `/views/layout/header.html`
и ещё полторы сотни таких же. Абсолютный путь отсчитывается от корня домена.

GitHub Pages кладёт обычный репозиторий в подпапку: репозиторий `portfolio`
окажется по адресу `folvski.github.io/portfolio/`. Тогда `/assets/css/main.css`
браузер пойдёт искать в `folvski.github.io/assets/css/main.css` — мимо папки
проекта. Результат: голый HTML без стилей, без скриптов и без секций, потому что
партиалы подгружаются по таким же абсолютным путям.

Репозиторий с именем `<ник>.github.io` — исключение: он публикуется **в корень
домена**. Пути начинают работать сами собой, переписывать ничего не нужно.

Такой репозиторий может быть один на аккаунт. Для портфолио это как раз тот случай.

---

## Шаг 1. Проверить, что Git установлен

Открой PowerShell и набери:

```
git --version
```

Если ответил номером версии — всё есть. Если «не является внутренней или внешней
командой» — поставь Git с https://git-scm.com/download/win и перезапусти PowerShell.

Первый раз нужно представиться — Git подписывает этим каждое изменение:

```
git config --global user.name "Folvski"
git config --global user.email "ssarockij@gmail.com"
```

---

## Шаг 2. Создать репозиторий на GitHub

1. https://github.com/new
2. **Repository name:** `Folvski.github.io` — ровно так, без пробелов и лишних слов
3. **Public** (на бесплатном тарифе Pages работает только с публичными)
4. Ничего не отмечать в «Initialize this repository»: ни README, ни .gitignore,
   ни лицензию. Папка уже готова, пустой репозиторий проще соединить.
5. Create repository

---

## Шаг 3. Загрузить папку

Открой PowerShell **внутри папки `Site`**. Проще всего так: открой `Site`
в проводнике, зажми Shift, щёлкни правой кнопкой по пустому месту →
«Открыть окно PowerShell здесь». Либо вручную:

```
cd "C:\Users\PC\Desktop\Work\PORTFOLIO\Site"
```

> **Это важно.** Репозиторий заводится именно в `Site`, а не в `PORTFOLIO`.
> Во-первых, иначе сайт окажется в подпапке `/Site/` и все пути снова сломаются.
> Во-вторых, в `PORTFOLIO` лежат исходники макетов — одни только SVG-экспорты
> весят под две сотни мегабайт, и в публичном репозитории им не место.

Дальше по порядку:

```
git init
git add .
git commit -m "Портфолио: первая публикация"
git branch -M main
git remote add origin https://github.com/Folvski/Folvski.github.io.git
git push -u origin main
```

На `git push` откроется окно входа в GitHub — войди через браузер, дальше Git
запомнит доступ.

---

## Шаг 4. Включить Pages

Для репозитория `<ник>.github.io` публикация обычно включается сама. Проверить:

**Репозиторий → Settings → Pages.** Должно стоять:

- Source: **Deploy from a branch**
- Branch: **main**, папка **/ (root)**

Если не стоит — выставь и нажми Save.

Первая сборка занимает пару минут, дальше — меньше минуты. Готовый адрес
появится на той же странице:

**https://folvski.github.io**

---

## Как вносить правки дальше

Перезаливать сайт не нужно. Поправил файл, и:

```
git add .
git commit -m "коротко, что поменял"
git push
```

Уйдут только изменившиеся файлы. Поправил цвет в `tokens.css` — улетит один файл,
а не все двадцать мегабайт. Через минуту правка на сайте.

Если из трёх команд каждый раз не хочется — поставь **GitHub Desktop**
(https://desktop.github.com). Он показывает изменённые файлы списком, ты пишешь
строчку описания и жмёшь две кнопки: Commit и Push. То же самое, только мышкой.

## Что стоит знать на будущее

**Регистр букв.** На Windows `Merra.png` и `merra.png` — один файл, на серверах
GitHub это разные файлы. Картинка, которая прекрасно видна локально, на сайте
даст пустое место. Когда добавляешь новые файлы — сверяй имя в разметке с именем
на диске посимвольно.

**Служебные файлы в корне.** Рядом с `index.html` теперь лежат три штуки:

- `404.html` — страница «такой страницы нет». Pages ищет её строго в корне и ни
  в каком другом месте. Заглушка `pages/404.html` («кейс в разработке») осталась
  на месте, это разные вещи.
- `.nojekyll` — пустой файл-флажок. Без него GitHub прогоняет сайт через
  генератор Jekyll, а тот молча выбрасывает всё, что начинается с подчёркивания.
  Флажок отключает эту обработку.
- `.gitignore` — список того, что не надо загружать: системный мусор вроде
  `Thumbs.db` и настройки редакторов.

**Кнопка «Скачать CV».** Она ведёт на `/assets/cv.pdf`, а такого файла в папке
нет — сейчас это ссылка в никуда. Либо положи туда резюме, либо убери кнопку
из `index.html`.

**Свой домен.** Если позже купишь что-нибудь вроде `nesterenko.by` — его можно
привязать в Settings → Pages, поле Custom domain. Адрес `folvski.github.io`
при этом продолжит работать и будет вести на тот же сайт.
